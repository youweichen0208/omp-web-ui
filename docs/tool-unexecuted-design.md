# pi-harness · 工具调用未执行 指导文档

范围：模型把工具指令写成正文，pi 自动提醒后仍然没有发出工具调用。这种情况在对话流、顶栏和右栏怎么显示。
定稿方案：**33a**，取代 32a 里「工具调用解析失败」卡片的显示方式。
设计图：`tool-unexecuted-design.html`，打开后看 33a，可以切换四种状态。

---

## 1. 原来的问题（截图）

| 现象 | 问题 |
|---|---|
| 「工具调用解析失败」和「模型没有执行工具就结束了」两张满屏粉红卡上下叠着 | 同一件事显示成两次错误 |
| 自动提醒「你上一条回复里的工具调用…」显示在右侧的用户气泡里 | 看起来像用户自己写的 |
| 正文上方有「› 模型附加内容」，卡片里还有「查看原始输出」 | 同一份原文有两个入口 |
| 顶部有一个空的「system 03:13」 | 没有内容的消息占了一行 |
| 「换个模型重新发送」是 360px 宽的浏览器原生下拉框 | 和其他下拉不一致 |
| 右栏标题写着红色「中断」，下面却是「较长任务的进度会显示在此处」 | 状态自相矛盾 |
| 内容没超过一屏也显示「回到底部」，还显示「上下文 0% · 缓存 0%」 | 没用的信息 |

## 2. 流程和状态

```
模型回复里漏出工具指令（tool-text 检测到）
        │
        ▼
  ① 自动提醒中 ──提醒后模型发出了真实的工具调用──▶ 恢复正常（这次异常只留一行灰字）
        │
   提醒后仍然没有调用工具
        ▼
  ② 最终停住（显示一张「工具调用未执行」卡片）
        │
   用户点「重新发送」或「换个模型」
        ▼
  回到 ①，显示等待指示器
```

- 自动提醒最多 1 次。第二次仍然失败时停住，不再自动提醒。
- 同一次用户请求里，这些步骤都算**同一次异常**，用 `incidentId` 关联。

## 3. 对话流

### 3.1 第一次失败（两种状态都有）
在漏出指令的那条回复下面加一行：
```
✗ 工具指令写成了正文，没有执行 · 已自动提醒
```
- 12.5px 灰字，✗ 用 `--red`，「· 已自动提醒」用更浅的灰色。
- 不生成卡片，也不显示「模型附加内容」。

### 3.2 自动提醒事件
```
────────  ↻ 已自动提醒 pi 用工具调用重新发起 · 03:13  ────────
```
- 居中显示，12px，`--text-dim`，两边是 1px 的分隔线 `--border`。
- 鼠标悬停时，在提示框里显示提醒的原文。
- **不显示成用户气泡**，不参与编辑重问，问题导航里也不出现。

### 3.3 自动提醒中（状态 ①）
- 第一次失败的灰字下面，接 31a 的等待指示器，文案「理解你的问题」。
- 顶栏和右栏显示黄色「工作中」，输入框出现 ■ 停止按钮。

### 3.4 最终停住（状态 ②）
提醒事件下面是 pi 的第二次回复正文，正文后面接**一张**卡片：

```
┌──────────────────────────────────────────────────────┐
│ ✗ 工具调用未执行                    自动提醒 1 次后停止 │  ← 浅红底 --red-soft
├──────────────────────────────────────────────────────┤
│ fixture 把工具指令写成了正文，自动提醒后仍没有调用工具，  │
│ 任务停在这里。前面的结果都已保留。                      │
│ [重新发送]  [换个模型 ⌄]  查看原始输出                  │
└──────────────────────────────────────────────────────┘
```

| 部分 | 规格 |
|---|---|
| 卡片 | 白底 `--bg-elev`，1px 描边 `color-mix(in srgb, var(--red) 25%, var(--border))`，圆角 `--r-md` |
| 标题行 | `--red-soft` 底，内边距 9px 14px；✗ 用 `--red`；标题 600 字重，颜色比 `--red` 深一档；右侧 12px 灰字写尝试次数 |
| 说明 | 13px，`--text`；模型名直接写在句子里 |
| 重新发送 | 主按钮：`--accent` 底、白字，圆角 `--r-sm`，内边距 5px 14px |
| 换个模型 ⌄ | 次按钮：白底，1px `--border`，圆角 `--r-sm`；箭头用 15px 的 ⌄ / ⌃ |
| 查看原始输出 | 12.5px 灰色文字按钮 |

**不再出现**：
- 第二张红卡（「模型没有执行工具就结束了」）。
- 整张卡都是粉红底。
- 浏览器原生的 `<select>`。

### 3.5 查看原始输出
- 按时间列出每一次的原文：
  - 第 1 次 · 时间：漏出的 DSML / invoke 原文。
  - 自动提醒后 · 时间：第二次回复的正文，并注明「（没有工具调用）」。
- 等宽字体 12px，`--output-bg` 底，`white-space: pre-wrap; word-break: break-all`。

### 3.6 换个模型菜单
- 宽 260px，白底，1px 描边，圆角 `--r-md`，阴影 `0 12px 32px` 加 14% 透明度。
- 每行：模型名 · 来源（灰字）；当前模型用浅蓝底标出。
- 选择后：用这个模型重新发送上一条用户消息，菜单关闭，进入状态 ①。
- 键盘：↑↓ 选择，↵ 确认，Esc 关闭。

## 4. 顶栏和右栏

| 状态 | 顶栏 | 右栏 · 进度 | 输入框 |
|---|---|---|---|
| ① 自动提醒中 | 黄点「工作中」 | 黄点「工作中 · 用时」 | 显示 ■ 停止 |
| ② 最终停住 | 红点「中断」 | 浅红块：●「已中断」+「工具调用未执行。在对话里点『重新发送』继续。」 | 没有停止按钮 |

- 有计划时，右栏不显示上面的浅红块，改成当前步骤的图标变红，其他步骤不变。
- 没有计划时，**不显示**空状态的空心圆和「较长任务的进度会显示在此处」。
- 左栏当前对话的圆点和顶栏颜色一致。

## 5. 顺带清理

- **空的 system 消息**：没有可见内容的 system 消息不渲染，也不显示时间。
- **回到底部**：只在离底部超过一屏时显示。
- **上下文和缓存**：数值为 0 时隐藏。
- **模型附加内容**：同一条回复有「工具调用未执行」卡片时隐藏。

## 6. 文案

| key | 中文 | English |
|---|---|---|
| `toolUnexecutedTitle` | 工具调用未执行 | Tool call not executed |
| `toolUnexecutedAttempts` | 自动提醒 {n} 次后停止 | Stopped after {n} automatic reminder(s) |
| `toolUnexecutedHint` | {model} 把工具指令写成了正文，自动提醒后仍没有调用工具，任务停在这里。前面的结果都已保留。 | {model} wrote the tool instruction as text and still made no tool call after a reminder. Earlier results are preserved. |
| `toolUnexecutedInline` | 工具指令写成了正文，没有执行 | Tool instruction was written as text and not executed |
| `toolAutoReminded` | 已自动提醒 | Reminder sent |
| `toolReminderEvent` | 已自动提醒 pi 用工具调用重新发起 | Asked pi to retry with a real tool call |
| `toolRecoveryResend` | 重新发送 | Resend |
| `toolRecoverySwitch` | 换个模型 | Switch model |
| `toolRecoveryRaw` / `toolRecoveryRawHide` | 查看原始输出 / 收起原始输出 | View original output / Hide original output |
| `taskInterruptedHint` | 工具调用未执行。在对话里点「重新发送」继续。 | Tool call not executed. Use Resend in the conversation to continue. |

删除：`unexecutedToolTitle`（「工具调用解析失败」）、「模型没有执行工具就结束了」，以及 `toolRecoveryModel` 的长文案。

## 7. 实现要点

- `tool-text.ts` 检测到异常时，生成或沿用 `incidentId`，并记录是第几次（`attempt`）。
- 自动提醒发出的消息加上 `origin: "auto-reminder"`：
  - `Message.tsx` 遇到这种消息，渲染成事件行，不渲染成用户气泡。
  - 编辑重问、问题导航、折叠摘要、复制为 Markdown 都跳过它。
- 卡片只挂在同一个 `incidentId` 的**最后一次**回复上；前面几次只显示 3.1 的一行灰字。
- 「换个模型」用自定义菜单组件，复用输入框里模型下拉的列表和样式。
- 右栏的中断状态和顶栏用同一个数据源（`interrupted`），保证文案和颜色一致。

## 8. 验收

- [ ] 同一次异常，对话流里只有 1 张卡片和 1 条事件行。
- [ ] 自动提醒不出现在用户气泡、问题导航和编辑重问里。
- [ ] 有卡片时，「模型附加内容」不显示。
- [ ] 「换个模型」菜单可以用键盘操作，页面里搜不到原生 `<select>`。
- [ ] 中断时，右栏没有空状态的空心圆；顶栏、左栏、右栏的颜色一致。
- [ ] 内容不满一屏时，没有「回到底部」；数值为 0 时，没有「上下文 0%」。
- [ ] 390px、900px、1440px 宽度下，卡片按钮不溢出，菜单不超出屏幕。
- [ ] `npm run check:design` 通过。
