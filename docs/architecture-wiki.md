# Wiki 模式

点击文件树、全局搜索或工具卡片中的 `.md` / `.markdown` 文件，自动进入同一工作区的 Wiki 文档界面。顶栏在 Wiki 中显示「对话 | Wiki」两段状态切换；点「对话」返回聊天，再点 Markdown 文件重新进入。打开请求按 cwd + 路径 + 导航标识绑定；正文读取不依赖 conversationId，发送仍严格绑定目标原生会话，每次优先打开所点击的文件，不被上次浏览缓存覆盖；切换前先处理现有编辑器草稿。布局采用文档画布：250px 文件栏、760px 正文（容器 888px，含两侧各 64px 留白），以及默认打开的 400px 对话面板。面板关闭时显示底部 560px 输入胶囊，展开为 680px 卡片。面板与改动抽屉互斥；小于 1100px 时对话面板覆盖正文，正文宽度保持不变。小屏目录继续使用抽屉。正文字体复用本地 IBM Plex Sans / JetBrains Mono，标题使用本地 Source Serif 4 / Noto Serif SC 常用字子集 衬线字体，文案中英文同步。

## 原生 pi 边界

`WikiWorkbench` 把用户问题、当前文件、显式引用与选区组装为可预览的用户消息，经 `wiki-routes.ts` 调用当前 `ClientSession.prompt()`。系统提示词、原生工具和 SDK 生命周期保持原状。代码只读规则体现在可查看的请求文字和编辑器默认状态中；它是用户指令，不是工具沙箱。用户可在输入框切换「只改文档 / 可改代码」，或明确要求修改代码。范围、引用与选区仅提供上下文，不构成分析或修改任务；问候、闲聊按用户实际意图直接回复。修改及保存说明仅在用户明确要求编辑时生效，不能给每条消息追加无条件修改指令。

发送先保存有修改的文档；保存冲突或 SDK 预检拒绝时保留问题。HTTP 请求必须匹配 clientId、cwd、conversationId，扫描期间若切换会话则拒绝发送。SDK 的 `agent_settled` 触发本次文件版本记录；预检失败、停止等退出路径也会结束记录，不能把单次 `agent_end` 当作整个任务结束。运行中的 Wiki 请求不接收另一个 Wiki 请求或文件撤销。

选区工具条的「问 pi」将引用放入用户可编辑的输入并聚焦；链接操作直接插入文档。`@` 文件候选支持鼠标和键盘选择。右侧 `WikiChatPanel` 展示当前文档会话的用户消息、助手消息和实时增量。打开其他文档经过 App 草稿导航保护后，`new-conversation` 请求校验工作区、当前会话和目标文件，再调用原生 `newChat(true, true)` 创建独立会话。前端通过草稿保护后立即选择目标并先发出正文请求，再并行创建会话，避免 SDK 初始化占用事件循环拖慢正文。新会话创建串行执行，未开始的目标合并为最新选择；只有最新导航返回的会话 ID 与权威快照一致后才能发送。Wiki 容器只以 cwd 为 key，不随会话 ID 重建；准备期间可以编辑正文和输入问题，发送按钮显示「会话准备中」。初始化失败保留正文和输入，提供重试。旧会话消息不展示到新文档。创建成功后释放旧的空闲运行时，Wiki 聊天记录随临时会话释放，不写入历史文件；运行中或有终端的会话继续保留。同一文档内的目录跳转不创建会话。增量消息可能先于带 role 的快照到达，面板将该已知助手流归一为 assistant 后展示。

## 阅读交互

`wikiMetadata()` 优先使用 frontmatter title，再回退到第一个 H1；只在两者去空白后相同时从阅读视图移除第一个 H1，保留源文件和不同标题。阅读时间按 400 中文字/分钟及 200 英文词/分钟累计，排除代码块。更新时间区分今天、今年和跨年；引用篇数按来源文件去重。`WikiReading.tsx` 管理 H2 目录、底栏索引详情；正文采用34px/500 衬线标题、22px/500 衬线 H2、15px/600 无衬线 H3、14.5px/1.8 正文与 12px 元信息；更新日期、阅读时间和 #标签使用轻量灰底标签，保存状态位于顶栏文件名之后。代码块跟随应用外观，浅色使用浅灰底、深色使用暗灰底和语法高亮，右上角保留语言与复制按钮。独立 44px 插入工具栏常驻，选中文字时另有浮动格式栏，预览内编辑保持默认可用。

点开头的根目录归入「隐藏文件夹 · N」，展开状态存为项目级 `pi-wiki-hidden:<cwd>`；文件仍参与索引和搜索。顶栏「π 对话」及 Cmd/Ctrl+J 切换对话面板，收起只作用于当前文档；打开其他文档默认展开，不读取旧版项目级 `pi-wiki-chat:<cwd>` 偏好。面板收起时，输入胶囊点击或 `/` 展开，Esc 收起并保留草稿；编辑器和弹窗内的 `/` 不触发。发送成功自动打开面板，选区操作打开面板并将引用块带入共享输入框。范围菜单保留原始发送内容预览；用户消息右侧灰色气泡的悬停菜单提供完整发送内容、复制和重新发送；键盘聚焦和触屏也可打开。上下文为 0% 时隐藏，输入区当前文档只在范围下拉显示，不重复生成 chip。修改数量、查看和整次撤销入口紧邻对应助手回复。

`wiki-chat.ts` 只对回复中以粗体标题开头的 Markdown 列表项做建议卡片展示，其余原文保留。明确的 `§N`、`第 N 节`、`section N` 在当前文档存在对应 H2 时提供跳转；无编号标题使用 H2 顺序。跳转通过 Web Animations 高亮 1.5 秒，不修改编辑器 DOM 属性或原文；窄屏先收起面板以露出正文。未匹配的小节不提供跳转，不要求模型额外格式或注入提示词。

等待状态共用对话模式的 `ConversationWorkingStatus`（首次响应、工具运行、模型等待与断线）；思考内容共用 `ThinkingBlock` 并遵循相同显示偏好。工具调用默认一行，实际结果或实时工具状态决定成功、失败、运行中或中断；存在实测耗时才显示，可展开查看参数/结果。消息默认挂载最近 60 条，可加载更早记录；只有滚动接近底部时跟随增量。窄屏面板使用遮罩、dialog 语义和焦点循环。

## 文件与索引

`wiki-service.ts` 负责工作区索引、文档读取、搜索和文件历史；`wiki-links.ts` 定义标签与链接解析。HTTP 类型只在 `server/protocol.ts` 声明，经现有 type-only shim 供浏览器使用。

正文使用 `document-content`：仅校验目标真实路径，读取文件和元数据、SHA-256 版本，返回 `WikiDocumentContent`，不等待索引。引用使用独立 `document-references`（`WikiDocumentReferences`）；索引缓存各文件已解析链接及反向引用表，后台引用只更新链接，不覆盖编辑草稿。引用尚未返回时显示加载状态，不显示 0 篇。原 `document` 完整接口保持兼容。只读 HTTP 查询允许同项目原生会话切换；项目变化拒绝旧结果，写入/发送仍校验原会话。正文响应由组件存活状态和读取序号丢弃迟到结果。

- Markdown / txt 默认在渲染预览中直接编辑，复用 `RichMarkdownEditor` 的格式栏、斜杠插入、截图粘贴及段落原文保真。frontmatter 与重复 H1 在画布中隐藏但保存时保留；双链、目录及代码配色继续可用。Markdown 不提供源码/阅读切换；代码编辑共用保存机制，保存、冲突、发送前保存及导航保护沿用同一路径；运行和加载期间只读，自动保存期间仍可编辑。源码模式使用现有 `CodeFileEditor`。代码默认只读，可显式点击「编辑源码」手工编辑。保存只接受未截断的 UTF-8 文本，并比较原始字节 SHA-256。write 返回轻量 WikiDocumentContent，不等待引用索引；保存后后台刷新索引，点击发送立即显示「发送中」，失败保留输入。
- 标签读取 YAML 风格 `tags: [a, b]`、逐行列表与正文 `#标签`。通过 Markdown 语法树排除围栏、行内代码、缩进代码及链接地址；3/4/6/8 位十六进制颜色值不计为标签。解析结果用于索引元数据和标题下的 #标签；不提供标签筛选或 `#` 候选，原文件内容不变。
- `[[文件名]]`、`[[路径|显示名]]` 优先解析同目录、再解析工作区相对路径，最后只接受唯一的同名文件。重复文件名必须写明路径。Markdown 相对链接与行内代码文件路径也参与引用索引。反向链接包含来源路径和引用句子；每次展示 100 条，可继续加载，避免大型引用表阻塞正文交互。
- 文件树包含文档、代码、媒体和其他文件类型，依赖目录与 `.git` 等基础噪声目录除外；目录按需分页读取（每页 500 条），树行按可见窗口挂载。空目录保留。目录符号链接不递归建立索引，可以手动展开；读取必须通过真实路径边界检查。
- 搜索匹配文件路径与文本内容，结果按文档 / 代码 / PDF / 其他分组；支持方向键、Enter 打开、Cmd/Ctrl+Enter 引用给 pi。
- 索引最大 20,000 项、深度 32、文本单文件 2 MiB、总读取量 64 MiB。`WikiState.index` 返回已读取文件数、已发现文件总数、受限路径/字节数/原因；底栏入口打开详情，不再常驻顶部黄条。因项数、深度或目录权限中止扫描时标记 `totalIsLowerBound`，总数带 `+`，列出未扫描目录；没有扫描的后代不伪造数量。二进制文件仍按文件名索引，PDF 文本按搜索时提取；搜索最多返回 100 项。索引缓存约 30 秒，同一项目并发扫描合并；有缓存时立即返回并后台更新。进入/切换 Wiki 不强制扫描，手动刷新、保存和撤销会失效更新；任务前后撤销快照独立遍历最新文件并读取字节，不等待索引，也不解析 Markdown 元数据或引用。仅可见的 Wiki 轮询，普通周期 30 秒，任务运行及历史收尾期间缩短为 1 秒。
- PDF 使用 [PDF.js 的 Node API](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs) 提取文字，独立进程最多并行 2 个，每份 8 秒硬超时；每次搜索最多 8 份 PDF，每份 ≤20 MiB、≤200 页。纯扫描 PDF 需要已有文字层，当前不做 OCR。超限、加密或解析失败有结果限制提示。
- 图片与 PDF 走同源、鉴权、cwd 归属与真实路径检查的 `/api/wiki-media`。其他文件在浏览器中下载后打开；Electron 的固定 IPC 经本机服务校验当前工作区后调用系统默认应用。

## 改动记录与恢复

记录保存在 `<dataDir>/wiki/<real-workspace-hash>/`，与项目文件分离。每次 Wiki 提问开始前独立遍历并读取最新文件字节，任务结束后同样读取并比较；手工编辑保存单独记为「我」。新增、修改、删除与二进制改动均可恢复。列表仅提供短预览，展开大文件时读取完整前后版本。

历史按工作区保留最近 100 次有改动的请求，同时按 128 MiB 字节预算清理旧记录及未引用的内容文件。每次快照受 2 MiB 单文件、64 MiB 总量约束，未记录文件明确列出。记录比较请求期间观察到的磁盘版本；同时由外部编辑器或其他会话写入的文件也可能被包含。它不是 Git 事务或跨进程写锁；进程意外退出前未结束的请求不保证有完整撤销记录。

恢复支持整次请求和单个文件：先验证所有目标文件仍等于该记录的预期版本，再恢复原始字节；任一文件有后续修改则整组拒绝，保留现场。本进程写入失败会回滚本次已恢复的文件。撤销后可重做；新建文件的撤销为删除，删除文件的撤销为恢复。撤销不改写 pi 对话历史。

目录蓝点表示有未查看的 pi 改动。打开文件清除蓝点；当前打开文档的新段落用浅绿底显示，下一次查看或五分钟后淡去。正文标记仅用于阅读提示，完整的原始前后版本在改动抽屉中。

## 维护和验证

修改保存或撤销时运行 `tests/unit/wiki-service.test.ts`（版本、跨文件预检、二进制、路径边界、重启历史）；修改 API、PDF 或鉴权时运行 `tests/wiki-protocol-test.mjs`（已纳入 smoke）。导航性能与竞态运行 `tests/wiki-navigation-test.mjs`（500 文件、首次/切换/返回各 20 次，正文与会话延迟分开记录，5 秒初始化延迟、迟到响应、A→B→C、草稿和失败重试）。发送延迟运行 `tests/wiki-send-latency-test.mjs`（500 文件、真实浏览器与 SDK、本地模拟模型、普通发送和发送前保存）；UI 改动运行 `tests/wiki-ui-test.mjs`，它用本地模拟模型驱动真实 SDK `write` 工具，并验证文件切换、草稿、搜索、选区、批量恢复和手机布局。

Wiki 草稿保护与聊天文件预览分别注册导航守卫；只有脏草稿或保存中才拦截导航，先立即排空保存队列，成功后继续最新导航，失败才显示原有放弃/重试保护，避免 Wiki 隐藏后绕过聊天编辑器自己的保存保护。异步读取按文件序号与组件存活状态归属，工作区/文档切换时旧结果不得写入新页面，同项目会话准备不使正文读取失效。


### 导航性能复测（2026-10-05，本机 Chrome）

服务预先启动，以正文实际出现且编辑器 `contenteditable=true` 为就绪；会话就绪单独计时。500 文件隔离项目中，切换目标约 98 KB，首次进入、连续切换、返回 Wiki 各 20 次，编辑器 P95 分别为 235 / 338 / 341 ms，会话 P95 为 353 / 401 / 399 ms；正文 HTTP 请求 P95 为 18 ms。人为延迟索引/会话动作 5 秒时，正文仍在 1 秒内可编辑，发送保持禁用，初始化完成后草稿不丢失。

对本机 `blog/docs` 做只读浏览器复测，三种场景各 20 次，编辑器 P95 为 125 / 134 / 159 ms，会话 P95 为 162 / 164 / 205 ms，正文 HTTP P95 为 12 ms；读取文件哈希前后一致。独立服务读取 60 次的正文 P95 为 8.8 ms，包含冷索引的完整接口单次约 5.1 秒。以上是本机结果，不将大于 100 KB 文档或网络文件系统延迟计入 1 秒验收。

大文档单独复测：约 1 MiB 的纯 Markdown，三种场景各 5 次，编辑器 P95 为 727 / 1121 / 1233 ms，正文 HTTP P95 为 84 ms；测试时同时运行其他冒烟检查。当前没有可用的慢速网络文件系统，未测该场景。

### 发送前准备耗时（2026-10-05，本机）

修复前 `blog/docs` 只读复测 `WikiService.begin` 单次 3552 ms，主要耗时为发送前强制重建索引及引用解析。撤销快照独立读取最新字节后，20 次 P95 50 ms、最大 99 ms。该指标不包含原生会话初始化及模型网络响应，未调用模型、未修改用户项目文件。

完整发送链路在隔离的 500 文件项目中验证：点击到原生 prompt 接受，普通 hello 为 85 ms，先保存草稿再发送为 89 ms；模拟模型延迟独立于发送准备。

## Wiki 临时聊天

新 Wiki 对话使用 SDK 原生 `SessionManager.inMemory(cwd)`，聊天内容仅保存在内存中，不创建 transcript，不进入项目普通历史或默认最近会话恢复。离开文档或返回普通聊天后释放空闲 Wiki runtime；再次进入新建空会话。正在执行的任务不因视图切换而被中断，临时保留入口以便停止，结束且无终端后释放。保留有终端的 runtime，避免误杀用户或代理启动的终端。

返回普通对话自动创建普通原生会话，等待期间禁止向旧 Wiki 会话发送。普通新对话不复用空白 Wiki runtime；原生 `/new` 与强制中断恢复继续使用内存会话，不改变 SDK 和扩展加载。文档改动的撤销记录单独保留。旧版本已经生成的项目历史不自动批量删除。

回归：`tests/wiki-session-history-test.mjs` 验证 Wiki 聊天不落盘、项目历史为空及返回普通聊天后正常记录；`tests/wiki-ui-test.mjs` 验证切换文档产生新身份且无 transcript 文件。

## 22a 编辑态与自动保存

`use-wiki-autosave.ts` 在停笔 800ms 后保存，Cmd/Ctrl+S、导航及桌面关闭立即保存。写请求串行；每次使用最近确认的磁盘版本，响应只推进基线，不替换当前草稿。排空队列会继续保存等待期间输入的新内容。普通失败显示红点「保存失败 · 重试」，不循环重试；CAS 冲突返回 HTTP 409 / `WikiApiError.code = version_conflict`，保留草稿并显示「文件已在外部修改 · 重新载入 / 保留我的版本」。保留版本先读最新磁盘版本，再进行 CAS 写入，外部再次修改仍会冲突。元信息末尾显示黄点保存中、绿点已保存；顶栏不再有保存按钮或额外未保存文案。

桌面使用固定 `onBeforeClose` 桥等待保存，然后隐藏到托盘或退出；保存失败保留窗口和草稿。浏览器 beforeunload 立即尝试保存并保留原生离开保护，不能保证强制关闭进程或断电时异步请求完成。

Wiki 的 `/` 菜单在文本块开头或空格后触发，排除代码、链接、列表和保护块。中文、英文、拼音及旧别名均可搜索；空格/标点关闭，方向键选择、Enter 插入、Esc 关闭并保留输入。300px 单列、最多 8 行、上下翻转适配光标。顺序为正文、H1–H3、列表、编号、任务、引用、代码、提示、3×3 表格、分隔线、图片和文档链接；右侧显示 Markdown 记法。直接输入 `#`–`######`、列表、引用等前缀加空格转换块，H4–H6 保留这种入口。图片复用安全上传与相对路径保存；`[[` 打开文档搜索，普通链接支持 URL 输入。

选区浮条位于选区上方，空间不足时放下方，提供粗体、斜体、H2、H3、链接、黄/绿背景和问 pi。再次点击同色清除标记；继续使用已有固定色值 mark 序列化和原生撤销栈，已有五色标记可正常读取。撤销/重做只用快捷键，普通文件预览仍保留其格式栏。完整索引成功后隐藏底栏索引项，有未完成/跳过项仍保留详情；状态栏不显示消息计数。

新 Pi 改动记录携带服务端采集的 `conversationId`、`requestId` 和最终助手 `assistantTimestamp`。只有同一会话的对应回复展示非空改动；旧记录无归属信息，只在最近改动中展示。查看会读取完整 diff 并在正文标记新增段落，后台装饰不改变草稿；撤销仍按整个请求做版本预检。

回归：`tests/wiki-editing-test.mjs` 覆盖延迟确认期间继续编辑、立即导航保存、失败重试、冲突处理、紧凑菜单、Markdown 简写、选区格式和窄屏；`tests/wiki-desktop-save-test.mjs` 在真实 Electron 验证关闭、退出及失败保留窗口；`tests/wiki-ui-test.mjs` 验证回复改动归属与完整消息菜单。设计稿待定的 AI 续写/总结命令、最近使用分组及问 pi 结果替换流程未加入。

## 扩展 UI 与恢复状态

Wiki 复用当前对话的扩展弹窗、多行 editor、输入替换和原生恢复状态。后台权限请求点击切换仍经过 Wiki 草稿离开保护。临时会话释放时关闭其弹窗并销毁 UI 上下文；断线保留服务端有效请求，重连重放。输入替换按对话消费一次，不自动提交。运行阶段、取消及会话级开关的协议见 [核心架构](architecture-core.md)。

## 品牌对齐 25a / 26a

统一使用图标蓝与暖白表面，Wiki 跟随应用浅色/深色主色；发送按钮无输入时灰色、可发送时蓝色、运行中为深色停止按钮。侧栏使用 24px 无底板矢量标志，顶栏与 pi 头像为 18px；favicon / Apple touch icon 使用第 14 版 1a-flat 的 32/180px PNG，安装包图标维持原样。选中文件带 2px 蓝色竖条，零引用隐藏，刷新按钮默认灰色、悬停蓝色。

空对话的说明与快捷问题靠近输入框。文档默认提供“总结这篇文档”和“找出失效链接”；排除 frontmatter 与代码示例后，有空标题才提供“补全空的小节”。点击沿既有保存/发送守卫直接发给当前文档的原生会话，范围强制为当前文档，不继承整个工作区或其他引用，不增加生成快捷问题的模型请求。

## 文档画布视觉更新（2026-10-08）

34a 规范见 `wiki-doc-v2-design.md`。顶栏显示目录路径、文件名、保存状态、最近改动和对话开关。`WikiToolbar` 提供分组 SVG 插入按钮；`TableSizePicker` 支持 8×6 鼠标/键盘选择；`CodeLanguagePicker` 支持搜索和 Mermaid。更多菜单与斜杠菜单共用插入项。Mermaid 图和代码并存，图形装饰标记 `data-rich-ui`，保存时剔除。

宽版隐藏两侧并使用 1000px 正文；打开对话、新文档或最近改动退出。宽版不持久化。正文维持 800ms 自动保存、Cmd+S 和导航保存，未编辑块保留原文。默认焦点位于文末；空段落提示不写入 Markdown。本地字体仅用于标题，以 unicode-range 按需加载，并随文件附带 OFL 许可证。
