# Wiki 模式

点击文件树、全局搜索或工具卡片中的 `.md` / `.markdown` 文件，自动进入同一工作区、同一 pi 会话的 Wiki 文档界面。顶栏不再提供独立 Wiki 模式入口；点「对话」返回聊天，再点 Markdown 文件重新进入。打开请求按 cwd + conversationId 绑定并带唯一标识，每次优先打开所点击的文件，不被上次浏览缓存覆盖；切换前先处理现有编辑器草稿。布局按 19a 右侧对话稿：250px 文件栏、最大 740px 文档正文，以及默认打开的 400px 对话面板。面板关闭时显示 200px 本页目录（小于 1200px 隐藏）和底部 560px 输入胶囊，展开为 680px 卡片。面板与改动抽屉互斥；小于 1100px 时对话面板覆盖正文，正文宽度保持不变。小屏目录继续使用抽屉。字体复用本地 IBM Plex Sans / JetBrains Mono，文案中英文同步。

## 原生 pi 边界

`WikiWorkbench` 把用户问题、当前文件、显式引用与选区组装为可预览的用户消息，经 `wiki-routes.ts` 调用当前 `ClientSession.prompt()`。系统提示词、原生工具和 SDK 生命周期保持原状。代码只读规则体现在可查看的请求文字和编辑器默认状态中；它是用户指令，不是工具沙箱。用户可在输入框切换「只改文档 / 可改代码」，或明确要求修改代码。

发送先保存有修改的文档；保存冲突或 SDK 预检拒绝时保留问题。HTTP 请求必须匹配 clientId、cwd、conversationId，扫描期间若切换会话则拒绝发送。SDK 的 `agent_settled` 触发本次文件版本记录；预检失败、停止等退出路径也会结束记录，不能把单次 `agent_end` 当作整个任务结束。运行中的 Wiki 请求不接收另一个 Wiki 请求或文件撤销。

选区动作（问 pi / 改写 / 解释 / 加双链）填写用户可编辑的输入。`@` 文件候选支持鼠标和键盘选择。右侧 `WikiChatPanel` 展示当前文档会话的用户消息、助手消息和实时增量。打开其他文档经过 App 草稿导航保护后，`new-conversation` 请求校验工作区、当前会话和目标文件，再调用原生 `newChat(true)` 创建独立会话。前端将文档绑定到返回的会话 ID，等待相应快照后才能发送。创建成功后释放旧的空闲运行时，原生历史文件仍保留；运行中或有终端的会话继续保留。同一文档内的目录跳转不创建会话。增量消息可能先于带 role 的快照到达，面板将该已知助手流归一为 assistant 后展示。

## 阅读交互

`wikiMetadata()` 优先使用 frontmatter title，再回退到第一个 H1；只在两者去空白后相同时从阅读视图移除第一个 H1，保留源文件和不同标题。阅读时间按 400 中文字/分钟及 200 英文词/分钟累计，排除代码块。更新时间区分今天、今年和跨年；引用篇数按来源文件去重。`WikiReading.tsx` 管理 H2 目录、底栏索引详情；代码块沿用设置中的代码配色并显示语言与复制按钮。

点开头的根目录归入「隐藏文件夹 · N」，展开状态存为项目级 `pi-wiki-hidden:<cwd>`；文件仍参与索引和搜索。顶栏「π 对话」及 Cmd/Ctrl+J 切换对话面板，收起只作用于当前文档；打开其他文档默认展开，不读取旧版项目级 `pi-wiki-chat:<cwd>` 偏好。面板收起时，输入胶囊点击或 `/` 展开，Esc 收起并保留草稿；编辑器和弹窗内的 `/` 不触发。发送成功自动打开面板，选区操作打开面板并将引用块带入共享输入框。范围菜单保留原始发送内容预览；修改数量和撤销入口位于面板底部，收起时位于胶囊上方。

`wiki-chat.ts` 只对回复中以粗体标题开头的 Markdown 列表项做建议卡片展示，其余原文保留。明确的 `§N`、`第 N 节`、`section N` 在当前文档存在对应 H2 时提供跳转；无编号标题使用 H2 顺序。跳转通过 Web Animations 高亮 1.5 秒，不修改编辑器 DOM 属性或原文；窄屏先收起面板以露出正文。未匹配的小节不提供跳转，不要求模型额外格式或注入提示词。

等待状态共用对话模式的 `ConversationWorkingStatus`（首次响应、工具运行、模型等待与断线）；思考内容共用 `ThinkingBlock` 并遵循相同显示偏好。工具调用默认一行，实际结果或实时工具状态决定成功、失败、运行中或中断；存在实测耗时才显示，可展开查看参数/结果。消息默认挂载最近 60 条，可加载更早记录；只有滚动接近底部时跟随增量。窄屏面板使用遮罩、dialog 语义和焦点循环。

## 文件与索引

`wiki-service.ts` 负责工作区索引、文档读取、搜索和文件历史；`wiki-links.ts` 定义标签与链接解析。HTTP 类型只在 `server/protocol.ts` 声明，经现有 type-only shim 供浏览器使用。

- Markdown / txt 默认在渲染预览中直接编辑，复用 `RichMarkdownEditor` 的格式栏、斜杠插入、截图粘贴及段落原文保真。frontmatter 与重复 H1 在画布中隐藏但保存时保留；双链、目录及代码配色继续可用。预览和源码共用草稿，保存、冲突、发送前保存及导航保护沿用同一路径；运行、加载和保存期间只读。源码模式使用现有 `CodeFileEditor`。代码默认只读，可显式点击「编辑源码」手工编辑。保存只接受未截断的 UTF-8 文本，并比较原始字节 SHA-256。
- 标签读取 YAML 风格 `tags: [a, b]`、逐行列表与正文 `#标签`。通过 Markdown 语法树排除围栏、行内代码、缩进代码及链接地址；3/4/6/8 位十六进制颜色值不计为标签。解析结果仅保留在索引元数据中；界面不提供标签列表、标题标签、标签筛选或 `#` 候选，原文件内容不变。
- `[[文件名]]`、`[[路径|显示名]]` 优先解析同目录、再解析工作区相对路径，最后只接受唯一的同名文件。重复文件名必须写明路径。Markdown 相对链接与行内代码文件路径也参与引用索引。反向链接包含来源路径和引用句子。
- 文件树包含文档、代码、媒体和其他文件类型，依赖目录与 `.git` 等基础噪声目录除外；目录按需分页读取（每页 500 条），树行按可见窗口挂载。空目录保留。目录符号链接不递归建立索引，可以手动展开；读取必须通过真实路径边界检查。
- 搜索匹配文件路径与文本内容，结果按文档 / 代码 / PDF / 其他分组；支持方向键、Enter 打开、Cmd/Ctrl+Enter 引用给 pi。
- 索引最大 20,000 项、深度 32、文本单文件 2 MiB、总读取量 64 MiB。`WikiState.index` 返回已读取文件数、已发现文件总数、受限路径/字节数/原因；底栏入口打开详情，不再常驻顶部黄条。因项数、深度或目录权限中止扫描时标记 `totalIsLowerBound`，总数带 `+`，列出未扫描目录；没有扫描的后代不伪造数量。二进制文件仍按文件名索引，PDF 文本按搜索时提取；搜索最多返回 100 项。索引缓存约 3 秒，只在可见的 Wiki 模式刷新。
- PDF 使用 [PDF.js 的 Node API](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs) 提取文字，独立进程最多并行 2 个，每份 8 秒硬超时；每次搜索最多 8 份 PDF，每份 ≤20 MiB、≤200 页。纯扫描 PDF 需要已有文字层，当前不做 OCR。超限、加密或解析失败有结果限制提示。
- 图片与 PDF 走同源、鉴权、cwd 归属与真实路径检查的 `/api/wiki-media`。其他文件在浏览器中下载后打开；Electron 的固定 IPC 经本机服务校验当前工作区后调用系统默认应用。

## 改动记录与恢复

记录保存在 `<dataDir>/wiki/<real-workspace-hash>/`，与项目文件分离。每次 Wiki 提问开始前记录文件字节，任务结束后比较；手工编辑保存单独记为「我」。新增、修改、删除与二进制改动均可恢复。列表仅提供短预览，展开大文件时读取完整前后版本。

历史按工作区保留最近 100 次有改动的请求，同时按 128 MiB 字节预算清理旧记录及未引用的内容文件。每次快照受 2 MiB 单文件、64 MiB 总量约束，未记录文件明确列出。记录比较请求期间观察到的磁盘版本；同时由外部编辑器或其他会话写入的文件也可能被包含。它不是 Git 事务或跨进程写锁；进程意外退出前未结束的请求不保证有完整撤销记录。

恢复支持整次请求和单个文件：先验证所有目标文件仍等于该记录的预期版本，再恢复原始字节；任一文件有后续修改则整组拒绝，保留现场。本进程写入失败会回滚本次已恢复的文件。撤销后可重做；新建文件的撤销为删除，删除文件的撤销为恢复。撤销不改写 pi 对话历史。

目录紫点表示有未查看的 pi 改动。打开文件清除紫点；当前打开文档的新段落用浅绿底显示，下一次查看或五分钟后淡去。正文标记仅用于阅读提示，完整的原始前后版本在改动抽屉中。

## 维护和验证

修改保存或撤销时运行 `tests/unit/wiki-service.test.ts`（版本、跨文件预检、二进制、路径边界、重启历史）；修改 API、PDF 或鉴权时运行 `tests/wiki-protocol-test.mjs`（已纳入 smoke）。UI 改动运行 `tests/wiki-ui-test.mjs`，它用本地模拟模型驱动真实 SDK `write` 工具，并验证文件切换、草稿、搜索、选区、批量恢复和手机布局。

Wiki 草稿保护与聊天文件预览分别注册导航守卫；只有脏草稿或保存中才拦截导航，避免 Wiki 隐藏后绕过聊天编辑器自己的保存保护。异步读取按文件序号与组件存活状态归属，工作区/会话切换时旧结果不得写入新页面。
