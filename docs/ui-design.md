# 工作区界面

运行状态以 `running-state-compare.html` 的 5b 为准：

- 命令卡片采用单行标题，只有实际截断或多行命令可展开；运行时显示紫色边框、呼吸点、分秒计时和灰色“停止”。复制、换行、全屏及折叠位于卡片菜单。可安全识别的 `cd 当前目录 &&` 从标题隐藏，其他字面目录移到目录标签，展开和复制保留完整原命令。
- Git short status 输出在每行均可解析时展示文件数及新增、修改、删除、冲突统计；状态独立一列，新增绿色、修改黄色。默认前三行与末三行，中间只有一条展开入口；混合或不可解析输出保持原文。
- bash 运行期间不重复显示“等待命令完成”及底栏“工作中”；读取和等待模型仍保留聊天区提示。输入框显示“继续输入，当前步骤结束后发送”和“停止任务”，与卡片上只停止 bash 的按钮区分。静默告警继续显示在输入区。
- 任务区以 `task-outline-design.html` 的 6b（完成态）和 6c（执行态）为准：顶部显示状态／“第 N / 总数 步”和耗时，下方显示任务标题；执行态附一句完成标准，不显示分段进度条。
- 步骤默认只显示勾选／序号、简短标题和耗时，当前步骤用紫色边框并显示实际动作。模块前缀不再单独显示，旧标题的括号细节与新计划的 detail 一并放入点击展开区；文件和命令按工具 ID 归属到具体步骤。
- 完成结果压成一行：提交、测试通过数、增删行数、“改动”；步骤仍默认可见，最终回复入口放进右上角菜单。计划新增、删除或调整后在底部明确说明，普通进度更新不会清除该说明。
- 任务运行且已有 Git 改动时，文件树收起未改动的顶层目录，“其余 N 个目录”可恢复展开；无改动或非 Git 项目保持完整目录树。

回归：`tests/agent-working-ui-test.mjs`、`tests/write-stall-ui-test.mjs`、`tests/unit/running-state-presentation.test.ts`。以上规则替代下文旧版运行状态、命令两行预览、计划标题换行及任务区布局的描述。

Web 与 Electron 共用同一套 React 布局与 `web/src/styles.css`。本次视觉参考为用户提供的 `pi-web-ui-standalone.html`（完整可运行参考），示例项目、消息和模型均由真实服务端数据替代。

- 左侧全高项目栏默认 264px：品牌、新对话、按最近使用时间排列的项目及当前项目的会话、设置（菜单中包含语言切换）。项目和会话行默认显示时间，悬停或键盘聚焦时以单个“更多”按钮替换时间；重命名、删除和移出项目都在菜单内，删除／移出须二次确认。项目显示展开箭头与会话数，折叠后保留计数；路径仅在悬停提示中显示，根目录与用户主目录分别显示为“根目录”和“~”。未手动命名的已完成问候会话在中文界面显示“打招呼”，顶栏与侧栏保持一致。
- 主区顶栏高 44px：视图使用下划线页签，当前页加粗并显示紫线；Git 显示工作区改动文件数，后台任务运行数用紫色。左侧开关无边框，macOS 位于原生红绿灯右侧；右侧开关用浅底，与页签用竖线隔开。标题后的当前计划步骤可点击，展开文件栏并聚焦任务区；非 Git 仓库时 Git 标签置灰并提供原因提示。
- 对话内容与输入框最大宽度 780px。消息滚动区顶部以 16px、底部以 56px 渐隐过渡；输入栏在滚动区外，末尾保留 24px 空间，短对话从底部向上排。用户消息靠右、浅紫底；模型与带“思考”标签的思考强度位于输入框底部，模型菜单向上展开。
- 用户粘贴的终端字符表格（多条箱线分隔符）保留为等宽块，块内横向滚动；普通长文本可在气泡内断行，超过八行默认折叠。`docs/xxx.md:行号` 在普通文本与字符表格中均可点击，打开右侧文件预览并定位行；Markdown 预览按源行号定位。文件栏没有 Git 改动时不显示“改动 0”，隐藏文件开关置于更多菜单。
- 首次模型回复还没有可见内容时，等待状态与计时直接显示在助手标题行，右侧时间保持原位；空思考块和空正文不占位。有内容后用思考块或正文接替等待状态，标题到第一块内容为 8px。等待 0–15 秒显示“正在分析请求”，15–60 秒显示“仍在思考”，60 秒起显示琥珀色“响应较慢”；服务端在约 180 秒发出 `agent_silence` 后，由输入框上方的状态行接管。关闭“完整显示思考”时，流式思考显示可展开的单行摘要。
- `/reload` 在对话中显示浅紫色等宽命令气泡和居中事件：进行中显示跳动点，完成时显示扩展／技能／提示模板数量与耗时，加载诊断以琥珀色提示并可展开路径和错误。悬停显示加载资源名称。侧栏等手动切换工作目录只更新界面状态，不弹成功通知；`/cwd` 等命令触发的切换在目标对话中显示居中目录事件。其他通知位于输入框正上方，使用细灰边框；普通通知 3 秒消失，错误和警告保留到手动关闭；快捷键提示只在空输入框获得焦点时出现。
- 文件栏默认 272px，可拖动调整及收起。目录原地展开，缓存已读取的节点；目录请求串行发送，切换项目清空缓存，隐藏时停止刷新。显示任务进度时，文件树按内容占用最多 45% 高度，进度区域独立滚动。文件标题行高 40px，标题后显示“改动 N”筛选入口。顶栏和文件栏共用 `useWorkspaceScm` 的 Git 状态，文件栏收起后仍响应改动事件刷新；请求使用负数 ID，与 SCM 面板隔离并按 cwd 校验归属；目录以数字标记改动数量，文件以 M/A/D 标记改动类型；“只看改动 (数量)”保留改动文件和祖先目录。非 Git 状态只在底栏显示；底栏路径对常见用户主目录使用 `~` 缩写。连接、分支、消息和路径统一放在全窗口底部的 32px 状态栏，避免出现两条高度不同的状态栏。
- 宽度 ≤1100px 时文件树使用抽屉。769–1200px 打开文档会收起项目栏，编辑器默认占剩余宽度的 45%，可拖动分隔条调整、双击恢复默认；可通过顶部按钮临时打开项目栏。≤768px 使用移动端抽屉。
- Bash 工具卡片采用浅色命令区与深色输出区。短的单行命令、输出行数和状态合并在标题行；长命令仍有可展开的完整命令区。输出默认显示前 5 行和末 3 行，省略处直接提供展开按钮，`git status --short` 的状态符号按改动类型着色；保留行号、路径分色、换行和真实剪贴板复制。思考块默认收起为“思考 · 耗时”，用户开启“完整显示思考”后展开；未记录的耗时不推测。服务端按对话、消息和块记录本次运行计时。
- 设置与目标入口收进左下角设置菜单；窄屏移至顶栏更多菜单。输入工具栏的思考档位是单个下拉按钮，显示“思考 · 当前档位”，菜单列出“极简／标准／深度”及说明，按模型支持的级别发送，精确级别仍可在模型菜单内选择。工作中空输入只显示停止按钮；有内容时才显示排队和插队发送。工具栏按输入框宽度依次截短模型名、隐藏缓存摘要、收起“思考”前缀，最后仅显示模型图标；用量弹窗只显示上下文窗口总量和缓存命中率，发送和停止按钮保持尺寸。
- 暖灰背景、深灰文字、紫色强调色；保留原紫色 π 图标。字体使用本地 IBM Plex Sans 与 JetBrains Mono，中文回退至系统字体。字体文件及许可证在 `web/public/fonts/`。
- 原文档编辑能力保持：15px 正文、浅色代码块、高亮块、图片细边框；`/` 菜单仅在普通空段落开头触发，列表内不触发。

检查：`npm run typecheck`、`npm run build`、`npm test`；浏览器交互见 `tests/file-editor-ui-test.mjs`，桌面编辑见 `tests/file-editor-electron-test.mjs`。

编辑器将返回、项目／文件路径、保存时间、预览／源码、查看改动、@引用及更多操作放在一行；保存按钮仅在草稿改动时出现，没有单独底栏。Markdown 默认在预览画布中直接编辑，修改先保留在草稿中，点击保存后写盘；源码视图使用同一草稿。打开文件自动将路径引用附加到当前对话，手动再次引用去重；预览或源码选区可用浮动按钮另附行号。Git 改动可在标题栏切换差异视图；编辑时遇到外部修改显示重新加载／对比提示。标题缩至约 27px／20px，行内代码跨行保留底色。聊天右侧的问题导航仅在悬停标记时显示深色小提示。编辑器与聊天默认按 45／55 分配剩余宽度，拖动分隔条后记住比例。表格单元格中的代码不折行，宽表格内部横向滚动。附件位于输入框内部，非零上下文占用至少显示 2px。目标服务生成的完整提示信封以居中事件行呈现，相邻相同目标合并计数，原始消息不变；普通用户消息不合并。

设计验收：`tests/workspace-design-ui-test.mjs` 使用隔离 Git 项目和零模型调用的测试消息，检查目录树、改动圆点、工具输出、复制、设置入口与三栏尺寸。

## 智能体工作中

连续的同模型助手步骤共用一个标题（工具结果不打断分组；用户／自定义消息或模型变化会分组）。首条助手消息尚未出现时，工作状态先显示同款 pi／模型／时间标题。原始消息 ID、搜索和编辑语义保留。聊天区只保留一条三点依次跳动的任务提示，按实际工具区分“正在运行 bash”“正在读取文件”，或分析／生成回复；前三秒隐藏计时，减少动态效果设置下停止动画。实时思考不显示折叠箭头，结束后恢复。底栏“工作中”使用同款三点动画，输入框不加工作状态圆点。

工作中输入框显示“排队”“插队发送”和停止；空输入时提示“继续输入消息…”，工作状态由底栏呈现。快捷键为 Enter 插队、⌘Enter（Windows 为 Ctrl+Enter）排队，结束后恢复普通发送提示。空输入时发送按钮禁用，排队使用 followUp、插队使用 steer。命令卡片统一提供换行、展开、全屏、复制、折叠；仅悬停／键盘焦点时显示，触屏常显；运行中的命令保留停止入口。命令默认工作区不重复标注，明确的其他路径才显示（当前用户目录缩写为 `~`）。只压缩带行号搜索结果冒号后的缩进，不修改普通代码空格；长输出可横向滚动，右侧尚有内容时显示渐隐边缘。

`tests/agent-working-ui-test.mjs` 验证工作状态、计时阈值、分组、两种发送指令、按钮一致性、改动筛选、输出滚动与回到底部按钮在 1600/900/390px 下对齐输入框；`tests/unit/agent-activity.test.ts` 验证分组边界、工具状态、路径与输出处理。

工作中输入内容后，“插队发送”采用深色主按钮，“排队”采用描边次按钮；空输入时两者隐藏。已记录的思考耗时从 1 秒起显示，未记录的耗时不推测。编辑工具的 diff 显示文件路径、实际非零增删统计、行号及整行底色；成功但无可用差异的编辑只保留操作记录，不显示 `+0` 或空差异区。文件栏提供隐藏文件开关，将改动数量收进筛选按钮；对话命令涉及的隐藏目录即使启用了改动筛选也保留，目录保留数字，文件显示 M/A/D。侧栏当前对话始终高亮，新对话置顶并立即可见；当天显示时间，昨天显示“昨天”，设置入口带齿轮图标；目标完成提示也使用与目标设定一致的事件行。

带 `=== 标签 ===` 的 bash 链按顶层 `;` 与 `&&` 分段，并依据实际输出标记显示已完成、失败和未执行步骤；命令在卡片里默认展示两行，展开后看全文，复制仍保留原始命令。SDK 将 stdout/stderr 合并，因此原始输出标为“输出”，对可识别的错误行用“疑似错误”提示并始终保留在折叠视图中；首尾及中间省略行数可见。代码区域禁用连字。右侧对话文件统一显示文件名和目录两行，靠得太近的问题导航标记合并显示数量，悬停列表仍可逐条跳转。

服务端将新产生的真实思考耗时写入 `<dataDir>/thinking-durations.json`，按会话文件和消息时间戳匹配，重启后仍可展示。此前没有记录耗时的旧消息保持未知，不填入估计值。

## 折叠对话与文件栏

历史消息摘要、展开消息和输入框共用 780px 内容宽度。摘要以与普通消息一致的灰色用户标记或紫色 π 标记识别角色；右箭头表示可展开，展开后用向下箭头收起。“回到底部”靠输入框右缘，停在输入框上方。命令卡片按钮垂直居中；grep 输出自带行号时复用该行号，不再叠加序号；横向溢出的内容在右侧渐隐。

非 Git 目录在文件栏和底栏明确显示“非 Git 仓库”，文件栏不显示改动筛选。文件栏不再展示“本次对话涉及”快捷列表。底栏显示服务端当前运行的版本号，Web 和 Desktop 共用。当前项目排在侧栏最前，其他项目按最近活动时间排列；项目行时间使用相同的活动时间。验收脚本 `tests/workspace-folded-ui-test.mjs` 使用隔离的非 Git 工作区和零模型调用消息检查这些状态。

相邻可见消息间隔超过 30 分钟时显示居中时间分隔线；消息时间和分隔线悬停可查看完整日期。思考行有无耗时均使用一致的箭头和文字基线，缺失耗时显示“未记录”；问题导航只标用户问题，标记高度按消息在整个滚动内容中的位置计算。输入框空白时即使获得焦点也保持灰色边框，只有聚焦且有输入内容时使用强调色；下方快捷键提示仅在消息输入区聚焦时显示。相关交互由 `tests/workspace-folded-ui-test.mjs` 验证。

代码文件默认用浅色纸面与低饱和紫／灰绿语法色，长行横向滚动；“更多”菜单可切换换行，只读阅读时续行使用悬挂缩进。设置 → 外观提供浅色、深色、跟随系统三种代码文件配色，偏好保存在当前浏览器；聊天命令输出始终保持深色。代码文件标题栏明确显示“只读／编辑”状态和 Git 改动入口；行号边显示新增、修改、删除标记，数据来自现有 SCM filediff 响应。消息导航标记位于聊天滚动条旁，默认隐藏，仅悬停导航区域或键盘聚焦时显示；编辑重问按钮悬停时位于气泡下方。

连续的 `read` 工具调用合成一条可展开的读取记录；工具结束后立即显示绿色“完成 · 耗时”，模型继续处理时由底部三点提示“等待模型”。展开的读取卡片以文件路径代替原始 JSON 参数，路径可打开完整输出；Markdown 的 YAML frontmatter 以小字段表显示，正文与代码输出默认仅显示前 10 行，可展开全部。技能卡片折叠时只显示技能名，完整路径保留在悬停提示与展开状态。回到底部按钮挂在输入区顶部的独立留白中，不遮住消息或工具卡片。相关回归覆盖于 `tests/agent-working-ui-test.mjs`、`tests/write-stall-ui-test.mjs` 和 `tests/unit/read-presentation.test.ts`。

`edit` / `write` 卡片标题显示操作、文件路径、增删行数和状态；“打开”定位到右侧文件面板，更多菜单保留原始参数和输出。正文使用深色逐行 diff（底色 `#22252B`、新增 `#223A2B`、删除 `#4A221D`，搭配浅色文字与语法高亮），旧／新行号分列，每处修改最多保留前后各两行上下文；SDK 未返回文件 diff 的成功编辑从替换参数展示变化行，并注明无法提供文件行号。相邻三次及以上编辑／写入合并为一张文件列表，单文件 diff 默认收起。超过 12 行可展开其余内容，空文件直接写明。失败卡片显示错误和寻找的原文；同文件后续编辑成功后，先前失败卡片收为一行。任务面板的增删数与卡片一致，点击数字跳回对应卡片。模型或工具连续静默时，输入框上方显示按对话绑定的状态行和操作，底栏、输入框使用相同状态；已有工具副作用的运行不提供自动重试。

右侧栏在存在 todo 清单时跨轮次显示任务进度；没有清单时，仅当前轮次调用工具后显示推断进度。进度由服务端从实际工具调用与结果推断；单阶段直接列出文件与命令，多阶段将连续步骤合并成语义阶段。短续接请求沿用上一任务名，找不到时从首个具体动作取名。事后归纳的任务显示“已完成 N · 进行中 N”，只在明确 `todo` 清单或历史 `task_plan` 时显示分段进度条和“第 N / 总数 步”；当前归纳阶段固定在滚动列表上方，当前计划步骤滚入可视区，耗时随运行更新。阶段标题用具体动作，摘要优先列命令、测试结果或文件名，已完成阶段用淡灰勾，仅当前阶段用紫色强调。仅从本轮记录提取已知提交、测试和改动数字；缺失时不显示，且结果卡只用于完成的多阶段任务。多阶段可展开过程，每阶段的原始步骤仅显示短摘要和工具记录，不重复助手回复；次要操作收进右上角菜单。文件可直接预览，步骤可跳回聊天对应消息；悬停工具卡片会高亮关联步骤。模型静默或长工具运行使用与输入框相同的状态源。任务摘要只呈现实际执行过的记录，不暗示正式计划或完成百分比的模型保证。

任务进度整理规则：服务端任务名取当前用户消息的首个完整意图；“继续”等短句沿用上一条实际任务标题。会话名称由侧栏和顶栏展示，右栏进度区从状态和步骤开始，避免重复标题。仅合并相邻且语义相同的原始步骤，每段执行记录仍可展开；阶段标题写动作，完成结果及工具计数写在标题下方；摘要最长 24 字。右栏计划步骤最多显示两行，完整文字保留在悬停提示；文件路径单行截断，完整路径也保留在悬停提示中。未预先规划的运行任务状态只显示工作中和实际用时。

明确进入实施阶段的长任务在 pi 调用 `todo` 后展示提纲：步骤随清单创建列出，当前步骤用紫色，已完成的打勾，待执行的保持浅灰，移除项划线保留，结构变化附说明。步骤数量建议 3–7，按实际任务调整。讨论和澄清遵循当前 skill，不强制列实施计划；工具卡片只表示计划已记录，不表示可以跳过等待，也不会要求额外确认。任务区的“只看结果”“原始段落”“复制为 Markdown”放在右上角菜单。

带 `echo "=== LABEL ==="` 标记且输出按同一顺序出现的 `&&` 命令，才显示“步骤／原始”切换；未标记或无法可靠对应的命令保持原始输出。步骤状态依据实际输出标记、结束状态和退出码推导；grep/rg 无匹配（退出码 1）呈灰色，不算失败。部分失败的步骤卡片默认展开失败项，仅错误行着红色；完全失败且有可解析 `file:line` 诊断时显示文件行号链接和可展开原始输出。链接打开工作区内文件并定位行，工作区外路径不打开。grep 工具调用显示可展开的搜索摘要。对应逻辑见 `web/src/bash-steps.ts`，回归见 `tests/unit/bash-steps.test.ts` 与 `tests/agent-working-ui-test.mjs`。

## SSH 节点工作台

节点页按来源设置、列表/详情、已连接工作台分层。详情页展示来源、认证缺失和不支持的选项；来源字段在原工具中修改。来源卡提供持续同步、一次导入、暂停/恢复和手动刷新。

连接后顶部保留节点标签，左侧深色终端、右侧浅色 pi 对话；窄屏上下排列。终端选择菜单将输出引用到当前节点的输入框，引用与草稿不跨节点。Agent 命令有紫色标记和结果卡片，定位时展示终端位置及捕获输出。确认卡包含允许、改命令与拒绝；SFTP 写入展示内容但不提供命令编辑。具体身份校验、凭据与同步规则见 `architecture-nodes.md`。

项目栏通过顶栏侧栏按钮收起／展开，拖动右边缘调整宽度；折叠与宽度记住浏览器偏好。顶栏不再显示“更多”，其设置、语言、声音及目标入口移至左下角设置菜单；侧栏收起或节点视图时以设置按钮提供入口。

任务操作记录使用双行布局：动作、增删数和输出行数在首行，命令／文件路径在下一行自然换行，命令字号 12.5px，不再强制单行省略。Windows 中文字体显式回退至 Microsoft YaHei UI／Microsoft YaHei；点击记录仍跳转完整工具卡片。

原生 todo 清单暂停时显示“等待继续”，保留未完成步骤和完成标准；展开步骤显示尚未完成的依赖。聊天中连续的成功 todo 更新合并为一张默认展开的“任务清单”卡，标题显示总项数和已完成数；卡片随清单最新成功状态更新。后续更新只插入浅色变化行（如“清单更新：第 1 项完成；第 2 项开始”），正文和其他操作分隔变化段；无变化的查询不重复展示。点击“查看”恢复历史卡片并滚动到变化项，高亮 1.8 秒，同时支持键盘聚焦和减少动画偏好。删除项划线保留，失败信息直接显示；缺少结构化结果的旧记录仍保留工具行。右栏固定展示完整当前清单，不重复展示 rpiv 的 TUI widget。清单跨轮次沿用，clear 后旧卡片留在历史中，新清单使用独立卡片；/new 后清空；历史 task_plan 卡片继续兼容。Web 与桌面共用展示，窄窗口标题可换行，任务正文按可用宽度折行。

任务区明确区分“任务清单”和“执行记录 · 未创建计划”；未调用 todo 时只展示执行记录，不伪造待办项。面板不显示 prompt 或清单总标题，从状态、耗时和记录来源开始，保留步骤标题与结果；复制 Markdown 时仍保留任务标题，数字或字母选项回复沿用前面的实质任务标题。多步骤实施的工具引导要求先创建或续用 todo、开始步骤前更新状态；旧会话首次继续实施时可补建剩余工作的清单，讨论和简单问答不要求建计划。

设置中的扩展名称按 npm 包名、入口所属目录名或独立文件名展示；index/main/extension/plugin 等通用入口不会直接作为名称，完整入口路径保留在说明中。随包加载的 rpiv-todo 显示为“rpiv-todo · 内置任务清单”，保留启停开关，不提供卸载按钮。显示名称与启停身份分离，禁用后仍保留可辨认的名称。

侧栏底部设置菜单首项为“所有设置”，不重复显示“设置”标题；目标、搜索和后台任务归入“快捷操作”，图标与文案靠左对齐。声音提示详情默认收起，展开后可调整开关、试听和音量；语言选项保持直接可见。节点页不显示设置菜单，不因项目栏卸载而回退到右侧顶栏；切入节点页会关闭已打开的设置菜单。

工具调用恢复提示按当前语言显示“正在纠正／工具已恢复／失败／未确认／未自动继续／已停止”，折叠摘要与正文使用同一文案。工具返回成功仅确认执行恢复，不宣称任务完成；原始异常回复保留，不直接执行其中的 XML 参数。

历史消息折叠摘要移除加粗、行内代码和链接等 Markdown 标记；助手摘要不重新展示已折叠的思考标记内容。正文中检测到思考标记时，原文保留在“模型附加内容”折叠区，提示解释检测原因，不将其描述为应用报错或数据泄露。

设置“组件更新”打开时检查 pi Agent 和扩展版本，列出已安装版本、上游版本及用户/项目/内置来源；有更新时显示计数。内置项解释“随应用版本升级”，不显示独立更新按钮。用户包按原来源更新，安装后显示重启提示；固定版本、本地源、检查失败均明确标识。失去连接时更新按钮禁用，重新连接重新检查。

## 原生 MCP

设置「原生 MCP」有全局/项目来源选择、stdio/HTTP 表单、args/env/headers/OAuth 结构化 JSON、启用和 exposure。完整 JSON 草稿保留高级及未知字段，保存前进行版本检查。官方连接状态与 OAuth 链接显示在管理页，交互弹窗在页内展示。Radius 登录成功后按钮显式写入全局 MCP，新名称避免覆盖同名配置。

## Markdown 文档界面（19a）

Markdown 文件点击后自动进入 Wiki，顶栏移除独立 Wiki 模式入口，点「对话」返回聊天。Wiki 使用 250px 目录栏、740px 最大正文宽度、200px H2 本页目录（小于 1200px 隐藏），输入框默认 560px 胶囊、展开 680px 卡片，以及 400px 按需改动抽屉。正文底部至少留 160px，回复和输入区域增高时追加滚动空间。索引状态放到底栏，隐藏文件夹归为可展开分组；移除标签展示与筛选，Markdown 预览默认可直接编辑。抽屉占据布局宽度，输入框在剩余主区居中。850px 以下目录切为抽屉，600px 以下改动面板在输入区域上方覆盖。文件类型、交互、历史与验证入口见 [Wiki 模式](architecture-wiki.md)。

## Codemode 与 MCP（15a / 15b）

聊天里的 Codemode 使用紫色 `{ }` 标记、工具计数 chips 和三个页签。默认只显示最后 8 条调用，每行保留状态、参数摘要和耗时，展开查看参数/错误。卡片整体可折叠，键盘左右键切换页签；图片操作和错误说明固定放在内容下方。只展示真实执行与费用数据，不提供审批暂停、回放或自动回滚。

设置页按「服务器 → 暴露方式说明 → Codemode → 原生 JSON」组织，连接问题优先排列，凭据继续掩码；下拉改动先进入草稿，保存后应用。桌面保持紧凑表格，窄屏折行操作区并允许内容区独立滚动。实现边界和数据来源见 `architecture-plugins.md`。

### Extensions 设置页

遵循 Extensions 第 1 轮设计：宽屏 1180px 设置容器，IBM Plex Sans / JetBrains Mono、紫色选中线、包列表细分隔线、版本锁定琥珀徽标。已安装与 pi.dev 目录双页签；目录两列卡片在窄屏降为单列。安装按真实来源预览、作用域和版本确认；未知资源清单直接标明。整包开关保留原生资源过滤，single-file 编辑独立弹层具有冲突和草稿保护。详见 architecture-extensions.md。

## 系统提示词设置（18c）

`SystemPromptPanel` 按原生顺序展示身份、工具、规则、Pi 文档、追加提示词、项目上下文。左侧浅灰固定标签、中部内容、右侧动作；IBM Plex Sans + JetBrains Mono，紫色编辑态。技能/cwd 仅在全文中显示。文件编辑在原行下方展开，支持范围选择、冲突重读、草稿离开保护。SYSTEM 替换先提醒，替换后三行说明变淡。强制提示词只读。详见 [系统提示词架构](architecture-system-prompt.md)。

## 设置窗口与外观

设置页按 20a 稿共用 `settings-modal`：最大 1240×800，桌面侧栏 216px，内容左右 40px、最大 820px。单层背景、细边框分组、至少 46px 的行，标题 19px，数量与版本用灰色小字，动作使用文字按钮。固定右上角关闭按钮，超长内容仅在右栏滚动；窄屏切图标导航并允许行内换行。保留系统提示词、技能、Extensions、MCP 与 Codemode、组件更新五页，默认打开系统提示词；不恢复消息显示与界面插件入口。

技能按行展示，点击展开完整简介；当前只展示原生已加载状态，未新增宿主技能过滤器。Extensions 按包、单文件、更新分组，保留浏览、安装及展开详情；自动检查使用开关。MCP 常用控件修改后自动保存，保存失败保留草稿并可重试。组件更新继续使用真实的检查、下载和安装能力，未新增无人值守更新策略。

已有的浅色、深色、跟随系统外观偏好继续生效，默认浅色；设置不再提供外观或代码配色控件。偏好以 `pi-web-ui:appearance` 存于浏览器。`appearance.ts` 更新根元素的 `data-appearance`，监听系统配色及跨标签页存储变化。已保存的代码文件配色继续独立生效。终端通过 `THEME_CHANGE_EVENT` 重新读取 CSS 调色板。

组件更新包含应用与原生扩展：桌面版通过固定 IPC 操作检查、下载并展示进度，下载后用户确认重启安装；开发桌面版不安装。浏览器版仅在 registry 版本高于运行版本时启用应用更新，打开可见终端执行固定 npm 包更新命令，完成后需重启服务。内置 Pi 随应用更新，本地单文件扩展提示编辑源文件，只有 `canUpdate` 的原生扩展显示更新按钮。

回归：`tests/component-updates-test.mjs --browser` 验证多宽度尺寸、外观持久化、系统配色和更新命令；`tests/app-updater-test.mjs` 验证更新生命周期；`tests/wiki-electron-test.mjs` 验证真实 preload 更新桥。
